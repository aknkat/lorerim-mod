# probe1：探知が表示されない問題の切り分け

**履歴用。probe1でも表示されず、その後に取得した実レコードからv0.1.1を作成した。現在の案内はREADMEを参照。この診断版を追加で試す必要はない。**

## 得られた実機情報

- 通常能力の使用後、`player.hasmagiceffect FECF5801` は `1.00`。制御MGEFは有効になっている。Papyrusの実行までは確認できない。
- `player.cast FECF5803 00000014 left` で内部探知を直接使用しても光らない。
- このとき `GetDead >> 0`、2件の `HasKeyword >> 0`、`GetIsRef >> 1.00` が表示された。
- 探知MGEFの該当条件は `GetIsReference PlayerRef == 0` なので、この評価対象では条件が成立しない。探知対象Actorのフィルターとしてだけ評価されるという当初の前提が誤っていた。

これはCabbage ENBだけの問題とも、NPCが追加MOD由来だから起きる問題とも断定できない。まず効果の適用を拒否する条件を切り分ける。

## このZIPの変更

`KhajiitKeenSenses-0.1.0-probe1-MO2.zip` は、公開済み通常版ZIPを基に、`LKS_DetectLivingEffect` の自己除外CTDAを1件だけ取り除く。通常版の生成ソースは変更しない。

- ESP名と4件のFormIDを維持する。
- 他のレコードと残り4条件は変更しない。
- 2秒、60秒、範囲の値、プレイヤー・種族制限は変更しない。
- PEX、PSC、6件のStringsは公開済みZIPとバイト単位で同一。
- 既存レコードの上書きは0件。

これは1条件の影響を調べる診断版。距離や死体・アンデッド・機械の除外、吸血鬼カジートでの動作は未確認であり、通常版の条件表テストの合格を実機動作の証明として扱わない。

## 導入と確認

1. ゲームを終了する。
2. MO2で診断用ZIPを元のMODへ **Replace（置き換え）** して導入する。同名ESPを複数のMODから同時に有効にしない。
3. 右側のIndexを確認する。`FE:CF5` のままなら以下のIDが使える。変わった場合はIDのインデックス部分を置き換える。
4. 生きたNPCのすぐ近くでコンソールに入力する。

   ```text
   player.cast FECF5803 00000014 left
   ```

5. コンソールを閉じ、約2秒光るか確認する。光らない場合は新たな出力も記録する。
6. 内部探知が表示できた場合に、60秒の制限終了後、通常の「鋭敏な感覚」を試す。直接キャストは制御スクリプトと60秒制限を経由しないため、別途確認が必要。

実機でprobe1の結果が分かるまでは、修正完了とは扱わない。恒久版に採用する条件配置、距離、除外対象の成立はその後に検証する。

## 再生成とファイル検査

```bash
python3 tools/build_detection_probe.py
```

公開済み通常版ZIPのSHA256を固定して入力を確認し、ESPの変更が対象CTDA1件だけであることを独立リーダーで照合する。全FormID、他レコード、スクリプト・Stringsの一致、ZIPのCRCとSHA256、連続した再梱包のバイト一致を検査する。この操作はビルド済みファイルに対する限定的な変更なので、.NET、Wine、Papyrusの再コンパイルは不要。
