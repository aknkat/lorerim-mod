# v0.1.3：入力効果と共有タイマーを分離

v0.1.2で押すたびに発動したという報告を受け、NoRecast単独の制限方式を廃止した。探知MGEFと内部SPELは、赤い表示を確認できたv0.1.1と同じデータを維持する。

## 所有関係

| FormID末尾 | 種類・役割 |
|---|---|
| 800 | Lesser Power。使用者・種族条件を持つ |
| 801 | 1秒の入力効果。旧EditorIDは互換性のため維持。NoRecastは無効 |
| 802 | 2秒の生命探知MGEF。表示・範囲・対象条件は変更しない |
| 803 | 内部探知SPEL。受理された発動時のみ呼ぶ |
| 804 | 新規の専用QUST。共有フラグと単発更新登録を所有する |

入力効果は毎回別のインスタンスになってもよい。状態は各入力効果に持たせず、同じ804のスクリプトへ要求する。804は入力用スクリプトからQuest.Startで開始し、StartGameEnabled、SEQ、Actor Alias、目標やジャーナル、ステージ断片を使わない。

## 受理と解除

`TryActivate` は待機中なら即座に拒否する。プレイヤー・キャスター・通常/吸血鬼Khajiit・探知SPELを検査した後に待機フラグを再確認し、次のNative呼び出しより先にフラグをTrueにする。その1回だけ、Quest上で `RegisterForSingleUpdate(60)` を登録して内部探知をCastする。

拒否された入力は探知をCastせず、タイマーも登録しない。`OnUpdate` はフラグをFalseへ戻すだけで、探知の自動再生や次の更新登録はしない。準備完了時の常駐ポーリングはない。起動した専用クエスト自体は停止までRunningのまま残る。

スクリプト変数とNativeの単発更新登録を使い、セッションごとに起点が変わるGetCurrentRealTimeの値は保存しない。保存後の残り時間はNativeの登録保存に従う設計。実際のSkyrimでのイベント配送、保存・ロードと負荷時の遅延は制作環境では未検証。

`Utility.Wait(60)` による実行途中のスタックは保持しない。TryActivateを終了し、別のOnUpdateイベントを待つ。それでも、保存したフラグと更新登録の整合性は実機確認が必要で、登録が復元されなければフラグだけが残って再使用できない可能性がある。ユーザー提供のLoreRim Safe Saving本文に従い、復元確認は保存後にゲームを終了・再起動して行う。進行中セッションから直接ロードしない。

## 検査の範囲

Capricaで実際にコンパイルした2つのPEXを独立リーダーで読み、命令を検査用ホストで実行する。TryActivateをPythonで書き直して検査するものではない。

- 初回発動、30秒での拒否、65秒での再使用。
- 毎回新しい入力効果を作り、200回再入力してもCastとタイマー登録が増えない。
- NativeのGetRaceや更新登録中に別要求が来ても、1回だけ受理される。
- 不正な使用者・種族、未設定プロパティ、Quest.Start失敗でCastやロックが生じない。
- 発動15秒後の変数と更新登録を保存し、ホスト時計の起点を変えて復元。45秒の残り時間を維持し、拒否入力で更新されない。
- 準備完了状態の復元で、探知や更新登録を勝手に再生しない。

更新登録、ゲーム時計とその保存復元は模擬したNative処理。これらの合格を、Skyrim本体での保存ロードや描画の合格とは区別する。

## 更新・解除

旧版をゲーム終了後にMO2でReplaceする。同じESP名と既存4件のFormIDを使い、能力の再付与は不要。2つのPEXとPSCを同梱し、コンパイル用APIスタブや他MODのスクリプトは導入しない。

外す場合は主能力をRemoveSpellし、通常画面で最後の発動から60秒以上待ってから、専用QuestをStopQuestして別名保存する。タイマー中にQuestだけを止める操作は通常の使用手順に含めない。確実に元へ戻すには導入前のセーブを使う。

Y長押し時の通知とY＋RT連打時の音の発生元は未特定。今回の版でキー登録や他MOD設定、ゲーム全体の失敗音・メッセージを変更しない。
