# 検証記録：v0.1.4

対象：Skyrim SE 1.6.1170 / LoreRim v5.0.4.8 Default / Requiem / Cabbage ENB。制作機でゲームは起動できない。**v0.1.4はファイルと模擬実行の検査に合格。実機での修正結果は未確認。**

## 実機報告

- v0.1.0とprobe1は探知が表示されなかった。標準VoiceAuraWhisper1は同環境で赤く広範囲に表示された。
- ユーザーの読み取り専用xEdit出力（3494 loaded files）で、Area/No Area/FX Persist/Actor Value、シェーダーとキーワードの最終定義、VMADを照合した。IndexはFE:CFD。詳細は [レコード比較](RECORD_COMPARISON_0.1.1.md)。
- v0.1.1で近くのNPCの赤い表示を確認。待機後は再使用できたが、途中の再入力後に初回から65秒経っても発動しなかった。
- v0.1.2は押すたびに発動し、NoRecast単独の制限方式は不成立だった。
- v0.1.3は60秒ごとの再発動を確認。ただし完全終了後でも、クールダウン中のセーブをロードすると1分以上待っても発動しない。待機中でなければロード後に即発動する。パワーを付け外しした後、直後でも正確な60秒後でもない途中のタイミングで発動すると報告された。
- 付け外し自体がスクリプトの待機を解除する実装はない。イベントの欠落・遅延や装備経路など、実機内部の根本原因はログで確定していない。セーブ破損を確認した報告でもない。
- Y＋RTでパワー発動。Y長押しで「no items to interact with」、Y＋RT連打で採取・飲食のような音。発生元は未特定。再使用待ち・残り時間は有効な効果に表示されない。他MODやキー設定の競合と断定しない。

## v0.1.4の変更と検査

解除イベントが届かなければフラグが永久に残る構成をやめ、入力時に標準プレイ時計と保存した期限を比較する。[変更の詳細](RELOAD_FIX_0.1.4.md)。旧版フラグは判定に使わない。新しい更新登録・Wait・Alias・ロード時の装備変更はない。

`python3 -m unittest discover -s tests -v`：**25 tests / OK**。実際にコンパイルしたPEXの命令を検査用ホストで実行する。API、時計とその保存復元は模擬で、ゲーム本体の時計・入力・描画は検証しない。

- ESL・Localized、Skyrim.esmのみへの依存、固有5レコード、既存レコードの上書き0件、解決するローカル参照と文字列。
- Lesser Power、Self、Fire and Forget、コスト0、1秒の入力効果、プレイヤーと通常/吸血鬼Khajiitのガード。自己参照HasMagicEffect条件なし。
- v0.1.3配布ZIPのSHA256を固定し、5レコードの全フィールドと入力PEXが同一であること。v0.1.1由来の探知データとも照合する。
- Area 27、Magnitude 0、Duration 2、FX Persist、Actor Value None、共通シェーダーDC209、Area Effect Ignores LOS。距離560 unitsと死体・アンデッド・機械・NoDetectLifeの条件表。
- 0/30/65秒の判定、200回の新規入力効果で期限が延びないこと。GetRace・時計取得・Cast中の再入でも受理が1回に留まること。
- **更新登録を一切復元しない**模擬ロードでも、発動15秒後に保存した期限が約45秒後に満了すること。準備完了状態でロードしても勝手に発動しないこと。
- 新しい期限のない旧セーブで、残ったTrueフラグが使用を妨げないこと。遅延した旧OnUpdateが新期限を解除しないこと。
- 時計が大きく巻き戻った場合に期限を一度だけ60秒先へ補正し、再入力で延長し続けないこと。
- 演算とAPI戻り値を32bit Floatに丸め、0/100/1000/10000時間で58秒時点の拒否と62秒時点の受理を確認。
- コンパイル済み制御に更新登録・Wait・装備変更の呼び出しがないこと。PEX構造・正しい長さ・破損ファイルの拒否。

ビルド・配布検査では、Caprica v0.3.0のstrictコンパイル、MutagenによるESP/PEXの独立読み込み、Pythonリーダー、Champollionの逆コンパイル、再現ビルド、ZIPのCRC/SHA256・Data配置、FSMPとのパス比較を行う。

旧版の検査ホストはNative更新登録が正しく復元されることを仮定しており、その仮定をゲームで検証できていなかった。v0.1.4では更新登録を失うケースも対象にするが、代わりに標準時計の進行・復元を模擬する仮定がある。25件合格をゲーム内の安全性の証明とは扱わない。

## LoreRimの運用ルール

ユーザー提供の [v4.lorerim.comのSafe Saving本文](https://v4.lorerim.com/home) に従う。公式サイトは制作環境のプロキシで403拒否されるため直接再取得しておらず、v5現行ページとの同一性も未確認。

ロードはゲームを終了・再起動してから行う。戦闘・重いスクリプト演出中・セル移動直後の保存、短い間隔での連続保存を避ける。保存した処理状態の不整合を持ち越すリスクを考慮し、確認には別名の検証用セーブを使う。軽量な処理や上書き0件でも、追加した保存状態のリスクはなくならない。

## 未確認の点

- **v0.1.4で待機中に保存・完全終了・再起動して、付け外しなしで残り時間後に発動すること。** ゲーム本体の標準プレイ時計と期限の復元、再入力・装備状態は未検証。
- 標準時計のメニュー・ポーズ・睡眠・ロード中の進み方、60秒境界の精度と大きなFloat値での丸め。時計補正時には正確な旧残時間を保持できない。
- v0.1.3からの既存セーブ更新と旧実行中スタック。新期限がない旧セーブは初回だけクールダウンをリセットする仕様であり、通常の保存復元の合格とは別。
- 実効半径約8m、2秒の正確な表示時間、除外対象、壁越しや自身の発光、吸血鬼Khajiit。近距離の赤い表示は過去のユーザー報告あり。
- 他MOD・将来の生成パッチやロードオーダーの変更、専用QUST停止・無効化後のセーブからの完全除去。

既存レコードの上書き0件は直接のレコード競合を避ける構成の検査結果であり、セーブやすべてのMODとの相互作用まで保証するものではない。
