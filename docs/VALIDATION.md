# 検証記録：v0.1.3

対象：Skyrim SE 1.6.1170 / LoreRim v5.0.4.8 Default / Requiem / Cabbage ENB。制作機でゲームは起動できない。**v0.1.3のゲーム内動作は未検証**。以下のファイル検査・模擬実行と区別する。

## ユーザー実機で確認されたこと

- v0.1.0は制御MGEFの有無を調べると1.00になったが、これはPapyrus実行の証明ではない。v0.1.0と自己除外だけを取り除いたprobe1では探知が表示されなかった。
- 同じ環境の標準VoiceAuraWhisper1は赤く広範囲に表示された。
- ユーザー提供の読み取り専用xEditエクスポートには、3494ファイルを読み込んだレコード情報がある。自作ESPのIndexはFE:CFD。Area/No Area/FX Persist/Actor Value、シェーダーとキーワードの最終定義、VMADを照合した。詳細は [RECORD_COMPARISON_0.1.1.md](RECORD_COMPARISON_0.1.1.md)。
- v0.1.1で近くのNPCが赤く表示された。60秒待つと再使用できるとの報告の後、途中で再入力すると初回から65秒後も発動しなかったと報告された。正確な距離と秒数、すべての除外対象は未確認。
- 操作はY＋RTでパワー発動。Y長押しだけで「no items to interact with」、Y＋RT連打で採取・飲食のような音が出る。再使用待ち・残り時間は有効な効果に表示されない。音・通知の発生元は未特定で、他MODやキー設定の競合と断定しない。
- 自己参照HasMagicEffect条件を外したv0.1.2では、**クールダウンに関係なく押すたびに発動した**。NoRecastと有限効果だけに任せた制限方式は不成立だった。v0.1.2の静的検査合格は、再使用制限のゲーム内動作を保証していなかった。

## v0.1.3の変更

入力効果を1秒に短縮し、60秒の制限を新規QUSTの共有スクリプトへ移した。最初の受理時にフラグを確保して単発更新を1回登録し、探知をCastする。待機中の入力は登録もCastも行わない。入力効果の再生成やNoRecastには制限を任せない。

探知MGEF（802）と内部SPEL（803）は表示できたv0.1.1と同一。800～803の既存IDを維持し、新規QUSTを804へ追加した。詳細は [COOLDOWN_CONTROLLER_0.1.3.md](COOLDOWN_CONTROLLER_0.1.3.md)。

## 制作環境での検査

`python3 -m unittest discover -s tests -v`：**19 tests / OK**。コンパイル済みPEXの実際の命令を検査用ホストで実行する。Native API・時計・更新登録とその保存復元は模擬している。

検査対象は次のとおり。

- ESL・Localized、Skyrim.esmのみへのマスター依存、2 MGEF + 2 SPEL + 1 QUSTの固有5件、既存レコードの上書き0件。
- Lesser Power、Self、Fire and Forget、コスト0、1秒の入力効果。入力MGEFはNoRecastに依存せず、自身の不在を要求する条件を持たない。
- 起動を入力スクリプトから行う専用QUST。StartGameEnabledなし、Alias・ステージ・目標・ジャーナル名なし。入力側4プロパティ、制御側3プロパティのVMAD参照とPEX型の一致。
- 0秒の発動、30秒の拒否、65秒での再使用。200回の新規入力効果でも、待機中にCastやタイマー登録が増えないこと。
- Native呼び出し中の再入要求でも受理が1回に留まること。不正な使用者・種族・キャスター、未設定参照、Quest.Start失敗時には発動しないこと。
- 発動15秒後のフラグと模擬Native更新登録を保存し、時計起点を変えて復元しても45秒の制限が残ること。準備完了状態の復元では勝手に再発動・更新登録しないこと。
- Area 27、Magnitude 0、Duration 2、No Area/No Duration無効、FX Persist有効、Actor Value None、共通シェーダーDC209、Area Effect Ignores LOS。
- 死体・アンデッド・機械・NoDetectLifeの条件表、560 units境界、自己適用を拒否する条件と敵味方判定がないこと。
- 英語・日本語の表示文字列参照、2つのPEXの構造と正しい長さマーカー、切れたPEXや別ゲーム形式の拒否。
- 公開済みv0.1.1から得たハッシュで、探知MGEFと内部SPELがバイト単位で同一であること。入力効果とスクリプトは今回の変更対象なので同一とは扱わない。

ビルドでは次も検査する。

- Caprica v0.3.0のSkyrim/strictモードで2スクリプトをコンパイル。
- MutagenでESPを生成し、別の読み込み経路で再読み込み。独立したPythonリーダーでもESPとPEXを解析。
- Mutagenの独立したPEXリーダーでも2ファイルの構造とオブジェクト長を照合。
- 配布ZIPの配置・CRC・全ファイルのSHA256。文書とマニフェストは固有フォルダーへ配置。

最終配布前の追加検査も合格した。

- Champollion v1.3.2が2つのPEXを読み込み、逆アセンブル・デコンパイルに成功。共有フラグの確保→単発更新登録→Cast、待機中の早期終了、OnUpdateでの解除を命令列で照合した。デコンパイルされたPSCでは入力側の入れ子のReturnが短絡式へまとめられるため、起動失敗時のReturnは逆アセンブル結果とPEX実行検査で確認した。
- 同じソースからの再ビルドで、ESP・2 PEX・ローカライズ・文書・配布ZIPのバイト一致を確認した。
- ユーザー提供FSMPアーカイブのMODルートからの相対パスを大文字小文字を区別せず比較し、重複0件。
- MO2用ZIPは22ファイル。ソースZIPには新規PSC・検査用ホスト・Quest用コンパイルAPIと文書を含み、他MODのバイナリやユーザー提供レコード全文は含まない。

これらはゲーム内のイベント配送や描画を検証するものではない。

## 未確認の点

- **Skyrim本体での正確な60秒制限、再入力時に期限が変わらないこと、更新イベントの配送、セーブ・ロード後の残り時間。** Native登録の保存復元を模擬したテストだけで、ゲーム側の保存形式を検証したとは扱わない。負荷によるPapyrusイベントの遅延もあり得る。
- v0.1.3への既存セーブ更新、起動した専用QUSTの保存と再使用、旧版の実行中効果が残る場合の挙動。
- 赤い表示が正確に約2秒で消えること、実効半径約8mと移動時の境界、屋内外・昼夜・壁越しの見え方。近距離の赤い表示はv0.1.1の報告のみ。
- 各除外対象、標準キーワードを持たない独自Actor、自身の発光、吸血鬼カジート。
- 待機・睡眠・セル移動、外部MODの作用、将来の生成パッチやロードオーダー変更。
- 専用QUSTを停止してMODを無効化した後のセーブ状態と完全な除去。

既存レコードの直接競合を生む上書きは0件。共有シェーダーやActorキーワードの将来の変更、すべてのMO2内ファイルとの相互作用まで保証したものではない。
